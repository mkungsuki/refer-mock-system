# Spec Sheet: appointment-system (ระบบตารางนัดเคสแพทย์ รพ.ชุมแพ)

**Date:** 2026-08-20
**Raw request:** "ทางบริหารบอกมาว่าอยากได้ระบบตารางนัดเคสของแพทย์เพราะจะได้ลดความแออัดและส่งตัวของรพ ตอนนี้กำลังคิดว่าวางแบบไหนได้บ้าง มี painpoint หลายจุด 1.เคสใน ward นัดมา 2.เคสใน opd นัดมา 1+2 แล้วเยอะกว่าที่คาด และบางทีแต่ละคนแผนก แต่ละแพทก็อยู่คนละวันจนสร้างระบบกลางยากมาก นอกจากนั้นยังมีเรื่องเคสที่ส่ง refer มาตรงวันบ้างไม่ตรงวันบ้าง บางทีส่งมาเป็น 10-20 ก็ไปทับกับไอ้ที่นัดมา 1+2 ที่คิดได้คือทำสลอต refer opd แยกออกมาว่าจะลิมิตเท่าไหร่ก็ขึ้กนับคนนั้นเอา แล้วตารางมันเห็นยาก ย้ายยาก ที่เคยทำตารางไว้ให้กดนัดง่ายๆและเห็นเลขก็น่าสนใจแบบที่เคยทำไปใน C:\AI-clinic แต่อันนี้อย่างที่บอกว่าหมอหลายคนและมี รพ อื่นมาร่วมด้วยอีกน่ะ เลยวุ่นกว่าเดิม"

## Problem

- **โจทย์:** ระบบตารางนัดกลางของแพทย์ทั้ง รพ. ที่รวมนัดจาก ward, OPD และ refer จาก รพ. เครือข่าย (รพช.) ไว้ในที่เดียว เพื่อคุมปริมาณเคสต่อวันไม่ให้ล้น และย้ายนัดได้ง่าย
- **ผู้ใช้:**
  - แพทย์แต่ละคน — ดูตารางตัวเอง, กดนัดเคสจาก ward/OPD, **ตั้งวันออกตรวจ + เพดานเคสของตัวเองได้เอง**
  - พยาบาล/เจ้าหน้าที่ OPD — ลงนัดแทนแพทย์, ย้ายนัด
  - ผู้ประสานงาน refer — จัดการสลอต refer
  - รพช. เครือข่าย (อนาคต) — เห็นสลอต refer ว่าง แล้วจองเอง
  - ทางบริหาร — ดูภาพรวมความแออัด
- **ทำไมต้องสร้าง:** รพ. มีระบบนัดอยู่แต่ รพช. มองไม่เห็น → ส่งตัวมาแบบสุ่ม คนไข้มาผิดวัน หรือมาซ้ำวันที่มีคนไข้อยู่แล้ว 60 ราย ไม่มีใครเห็นภาพรวมและนับเคสรวมต่อวันไม่ได้

## Deliverable (สำคัญ — เปลี่ยนเกม)

**Interactive mock/prototype ให้ผู้ใหญ่ใน รพ.ชุมแพ ดู** — ไม่ใช่ระบบ production
- ใช้ข้อมูลสมมติทั้งหมด (ไม่มี PDPA issue)
- โครงสร้าง/data model ต้องออกแบบเผื่อให้ IT เอาไปแปลงเป็นระบบจริงใช้ทั้งเขตได้
- คนตัดสินใจ: ผู้ใหญ่ใน รพ.ชุมแพ เท่านั้น (รพช. ไว้ค่อยให้ดูตอนจะใช้จริง)

## I/O Contract

- **Input:** นัดจาก ward (ตอน discharge), นัดจาก OPD (ตอนตรวจเสร็จ), refer จาก รพช. — แต่ละรายการ: HN, แพทย์, วันที่, ประเภท (ward/OPD/refer), หมายเหตุสั้น

### Data dictionary ต่อ 1 นัด (อิง FHIR Appointment — ให้ IT ต่อยอดได้)
| field | ที่มา/ใช้ทำอะไร |
|---|---|
| hn | ระบุผู้ป่วยฝั่งชุมแพ — เคส refer จาก รพช. เริ่มต้น **ไม่มี HN** ฝั่งชุมแพกด "ออก HN" ตอนลงทะเบียน |
| cid + pname + refNo | ตัวระบุข้าม รพ. สำหรับ refer: เลขบัตรประชาชน + ชื่อ + เลข ThaiRefer (รพช. ไม่รู้ HN ชุมแพ) |
| targetId | ช่องรับนัด (หมอ/pool/service/เครื่อง) |
| date + session | วันนัด + เช้า/บ่าย |
| type | ward / opd / refer (FHIR: serviceCategory) |
| icd | รหัสโรค ICD-10 ค้นได้ (FHIR: reason→Condition) — ฐานของ dashboard โรค |
| note | free text เสริม |
| from | รพ. ต้นทาง (เฉพาะ refer) — วิเคราะห์รายเครือข่าย |
| createdOn | วันสั่งนัด → คำนวณ lead time (นัดไกล no-show สูง) |
| status | booked / done / noshow (FHIR: status + fulfilled/noshow) — ฐานของ no-show rate |
| ระบบจริงควรเพิ่ม | ผู้ลงนัด, เบอร์ติดต่อ, ความเร่งด่วน, เหตุผลยกเลิก, เวลามาจริง (รอคิว) |
- **Output:**
  - ตารางรายวัน/รายสัปดาห์ต่อแพทย์ เห็นตัวเลข `นัดแล้ว/เพดาน` ชัด เปลี่ยนสีเมื่อใกล้เต็ม/เต็ม/เกิน
  - ตัวนับสลอต refer แยกจากนัดปกติ
  - ย้ายนัดด้วยการกดไม่กี่ครั้ง
- **Success criteria:**
  1. เห็นได้ใน 5 วินาทีว่าแพทย์คนนี้วันนี้มีเคสรวมกี่ราย เกินเพดานหรือยัง
  2. สลอต refer เต็มแล้วระบบบอกชัด ไม่ต้องนับมือ
  3. พยาบาล OPD ใช้เป็นภายใน 1 วันโดยไม่ต้องสอนซ้ำ
  4. (mock) ผู้ใหญ่ดูแล้ว "เก็ต" ทันทีว่าระบบแก้ปัญหา refer สุ่มมั่วยังไง
- ยังไม่มี KPI ทางการจากบริหาร

## Architecture Decisions Already Made (ห้าม re-debate)

1. **Mock มี 2 มุมมอง:** (1) ฝั่งชุมแพ — จัดตาราง/ลงนัด/ย้ายนัด (2) ฝั่ง รพช. — เห็นเฉพาะสลอต refer ว่างแล้วกดจอง → ภาพนี้คือจุดขายกับผู้ใหญ่
2. **เพดานเป็นระดับแพทย์ ไม่ใช่ระดับแผนก:** แพทย์แต่ละคนกำหนดวันออกตรวจ (รองรับ เช้า/บ่าย, บางคนออก 2 วัน บางคน 3 วัน) + เพดานเคสต่อวันของตัวเอง **แก้เองได้ง่ายๆ** — "ทำกลางมาเลยจะพัง"
3. **โควตา refer แยกจากนัดปกติ:** ปรับแยกกันได้ต่อแพทย์ต่อวัน refer เต็มคือเต็ม ไม่กินที่ ward/OPD
4. **ช่องทาง refer เฟสแรก:** ฝั่งชุมแพลงให้ (รับโทรศัพท์/ThaiRefer แล้วกดลง) — ให้ รพช. จองเองเป็นเฟสถัดไป (แต่ mock โชว์มุมมอง รพช. เพื่อขายภาพอนาคต)
5. **ขนาด mock — 6 แผนก แต่ละแผนกคนละโมเดลการนัด (ตั้งใจให้เห็นว่าโครงเดียวรองรับ constraint หลายแบบ):**

   | แผนก | โมเดลการนัด | จุดที่ต้องโชว์ |
   |---|---|---|
   | MED | **Pool รวมแผนก** — นัดเข้า pool ไม่ระบุหมอ ยกเว้นเคส d/c จาก ward ที่นัดเข้าหมอเจ้าของไข้ | pool + exception ต่อเคส |
   | SX | **เคสประจำตัวหมอ** — นัดเข้าหมอรายคน | doctor-based ล้วน |
   | ORTHO | เหมือน SX | doctor-based ล้วน |
   | NEURO | **ซอยย่อยจาก MED** — คลินิกเฉพาะทางแยกออกมา มีตาราง/เพดานของตัวเอง | subspecialty แยกจาก pool แม่ |
   | CARDIO | **Refer ขอ service เฉพาะ** เช่น echo, ตรวจเฉพาะ — สลอตผูกกับ service ไม่ใช่แค่ตัวหมอ | service-based slot |
   | XRAY | **นัดหัตถการ/เครื่อง** เช่น U/S — สลอตผูกกับ resource/หัตถการ | resource-based slot ไม่มีแนวคิด "หมอเจ้าของไข้" |

   ตารางออกตรวจหลากหลาย (2–3 วัน/สัปดาห์, เช้า/บ่าย) กระจายให้เห็นความวุ่นจริง
6. **ตัด drag-and-drop:** ย้ายนัดใช้กดเลือกปลายทางง่ายๆ พอ
7. **Data model กลาง:** ทุกนัดชี้เข้า "ช่องรับนัด" (slot target) ซึ่งเป็นได้ทั้ง หมอรายคน / pool แผนก / service (echo) / resource (เครื่อง U/S) — แต่ละช่องมีวันออกตรวจ+เพดาน+โควตา refer ของตัวเอง → นี่คือ abstraction ที่ทำให้ 6 แผนกอยู่บนโครงเดียวกันได้ และเป็นสิ่งที่ IT เอาไปต่อยอดได้ตรงๆ
8. **Custom field ต่อช่องรับนัด (แบบ REDCap/Epic flowsheet):** หมอ/คลินิกเพิ่มฟิลด์เก็บของตัวเองได้ (เช่น "ประเภทการมา: รับยา/Telemed/ตรวจ" ใน NCD) โดย (ก) จำกัดชนิด: dropdown (แนะนำ) กับ text เท่านั้น (ข) จำกัด 5 ฟิลด์/ช่อง (ค) คำตอบเก็บเป็น key-value (JSON) บนตัวนัด ไม่สร้างคอลัมน์ใหม่ในฐานข้อมูล (ง) ระบบกลางวิเคราะห์เฉพาะฟิลด์มาตรฐานร่วม ฟิลด์ส่วนตัวสรุปสถิติเฉพาะหน้าคลินิกตัวเอง → ฐานข้อมูลไม่พัง, IT ทำครั้งเดียวใช้ได้ทุกแผนก
9. **หน้าประจำ (pin):** ปักหน้าแผนก/หมอเป็นหน้าแรกได้ เปิดมาถึงทันที — ผูกกับบัญชี ไม่หลงเครื่อง
10. **บัญชีผู้ใช้ + สิทธิ์ตามบทบาท (mock เป็นหน้า login จำลอง ไม่มีรหัสผ่าน — ระบบจริงผูก AD/HOSxP):**
    - แพทย์: ปฏิทินตัวเองเป็นหน้าแรก · ลงนัดได้ทุกแผนก · แก้ตั้งค่า (วันออกตรวจ/เพดาน/ฟิลด์) ได้เฉพาะของตัวเอง
    - พยาบาลหน้าคลินิก: หน้าแรก = แผนกตัวเอง · **ลงนัดใหม่ได้ทุกแผนก (เข้าช่องว่างเท่านั้น — รองรับ consult ข้ามแผนก) แต่ย้าย/ยกเลิก/แก้สถานะนัดเดิมได้เฉพาะแผนกตัวเอง** — กันเคสเลื่อนนัดแผนกอื่นเพื่อยัดคนไข้ตัวเอง (กติกาเดียวกัน: หมอแก้ได้เฉพาะช่องตัวเอง, ศูนย์ refer แก้ได้เฉพาะเคส refer)
    - ศูนย์ refer: ลงนัดได้ แก้ตั้งค่าไม่ได้
    - บริหาร: หน้าแรก = dashboard · อ่านอย่างเดียวทั้งระบบ (ไม่มีปุ่มลงนัด/แก้)
    - บัญชี รพช.: ล็อกอยู่ฝั่ง refer ของ รพ. ตัวเองเท่านั้น เลือก รพ. อื่นไม่ได้
    - การนำเสนอ: ใช้ mock เดียว — หน้า login คือตัวสลับ mode สาธิตทีละบทบาทได้เลย
11. **Scale หมอเป็นร้อยคน:** target มี field `spec` (สาขาย่อย) — UI จัดกลุ่มตามสาขา + ช่องค้นหาเมื่อรายการยาว (ทั้งฝั่งชุมแพและ รพช.) · roster ใน mock ใช้โครงจริง: MED (gen 5 + nephro 2), NEURO 2, CARDIO (หมอ 1 + service 2), SX (gen 4 + neuro sx 1), ORTHO (gen 7 + sport 1 + spine 1) รวม 29 ช่อง / ~11,000 นัด
12. **บทบาท IT + กติกาข้อมูลตอนเพิ่ม/ถอดหมอ:** หน้า "จัดการระบบ" เพิ่มหมอ/สาขา/แผนกใหม่ได้ (เพิ่มแถวเดียว ไม่แตะโครงตาราง แล้วหมอไปตั้งวันเอง) · **ห้ามลบช่องที่เคยมีนัด — ใช้ "ปิดรับนัด" (archive)** เพราะนัด/สถิติอ้างด้วย id · เปลี่ยนชื่อ/ย้ายสาขาไม่กระทบประวัติ (อ้าง id ไม่ใช่ชื่อ) · IT ไม่มีสิทธิ์ยุ่งตัวนัด (separation of duty)

## Priority Tiers

- **P0 (must):** ตารางสัปดาห์ต่อแพทย์ + ตัวเลข นัดแล้ว/เพดาน + สีเตือน, ลงนัด ward/OPD, สลอต refer แยกพร้อมตัวนับ, หน้าตั้งค่าวันออกตรวจ+เพดานของแพทย์ (ง่าย), มุมมอง รพช. จองสลอต refer
- **P1 (should):** ย้ายนัดแบบกดไม่กี่ครั้ง, ภาพรวมทั้ง รพ. สำหรับบริหาร (วันไหนแน่นสุด)
- **P2 (nice):** พิมพ์ใบนัด, export, ประวัติการย้ายนัด

2. แจ้งเตือนสองทางเมื่อนัดถูกย้าย/ยกเลิก: SMS/โทรถึงคนไข้ + badge ฝั่ง รพช. (และกลับกัน)
3. ~~ระดับ urgency~~ **ทำใน mock แล้ว — นโยบายแทรกเกินเพดาน (กันลูป "ทุกคนด่วน") 4 ชั้น:**
   (ก) แทรกได้เฉพาะผู้มีชื่อรับผิดชอบ: หมอเจ้าของช่อง / ศูนย์ refer เฉพาะเคส refer — พยาบาลแทรกเองไม่ได้ (แบบ Epic overbook permission)
   (ข) บังคับเลือกเกณฑ์คลินิกจากรายการ (สงสัย CA 2 สัปดาห์, stroke fast track, เคสทรุด...) — ไม่มีตัวเลือก "ด่วนทั่วไป"
   (ค) เพดานแข็ง +10% — เต็มแล้วระบบปฏิเสธทุกกรณี ทางออกคือ waitlist/วันอื่น ไม่ใช่ยัดต่อ
   (ง) ทุกการแทรกติดชื่อผู้สั่ง + ขึ้น KPI ผู้บริหาร "แทรกเกินเพดาน × มากสุดที่ช่องไหน" — ความ visible คือตัวหยุด creep
   (แนว NHS: สลอต 2WW เป็นโควตากันไว้เฉพาะตามเกณฑ์ ไม่ใช่ overbook เสรี)
4. Waitlist เมื่อสลอตเต็ม + auto-notify เมื่อว่างจากการยกเลิก
5. Backend ต้อง check-and-reserve แบบ atomic ต่อ (target, date, session, bucket) — กัน 5 รพช. กดสลอตสุดท้ายพร้อมกัน
6. Worklist ตามเคส no-show (สถานะ ตามแล้ว/นัดใหม่/ติดต่อไม่ได้) — เคส refer มะเร็งที่หลุดนัดคือความเสี่ยงคลินิกจริง
7. Identity: บังคับ lookup HOSxP ก่อนบันทึก, validate CID 13 หลัก+checksum, กันจองซ้ำคนเดิมช่องเดิมวันเดิม
8. PDPA: mask CID บนใบนัด (x-xxxx-xxx45-xx-x), session timeout เครื่องส่วนกลาง
9. เปิด เสาร์/อาทิตย์ ใน schema (คลินิกนอกเวลา) + cutoff refer จองล่วงหน้า ≥ 1 วันทำการ
10. Nice-to-have: เบอร์คิว/ช่วงเวลาย่อยในครึ่งวัน + QR check-in, auto-search ถ่วงน้ำหนัก "รวมนัดวันเดียวกัน" สำหรับคนไข้หลายแผนก, export Excel จาก dashboard, slot duration ต่อประเภทหัตถการ
